# مشاكل مؤجل الحل

> هذا الملف مخصص لتسجيل المشكلات المؤجلة التي تم تشخيصها أو إثباتها، ولكن تقرر عدم تعديلها ضمن المرحلة الحالية، للعودة إليها لاحقًا في مرحلة مستقلة.

## المشكلة: معمارية المصادقة في Web SPA واستخدام `wsa_token`

**الحالة:** مؤجلة — لا يتم تعديلها الآن.

**الأولوية:** لاحقة / مشروع مستقل لترحيل المصادقة.

### الخلاصة المثبتة

تم إجراء تدقيق معماري كامل لاستخدام `wsa_token`، والنتيجة أن الرمز **مطلوب حاليًا لتشغيل Web SPA للمستخدمين المسجلين** في المعمارية الحالية.

المسار الحالي هو:

```
Web SPA
  ├── CSRF Cookie / Session → حماية طلبات POST وتدفق Sanctum
  └── wsa_token (Personal Access Token)
        └── Authorization: Bearer
              └── auth.principal → هوية المستخدم في الـ API
```

إزالة `wsa_token` الآن، من دون بناء بديل للمصادقة عبر جلسة Sanctum، ستؤدي إلى تعطيل معظم الوظائف المحمية في Web SPA.

### الأدلة التي تم إثباتها

- لا يوجد حاليًا تسجيل دخول للمستخدم عبر `Auth::login` أو `guard('web')->login` ليجعل Session Cookie مصدر هوية المستخدم في API.
- مجموعات الـ API المحمية تعتمد على `auth.principal` وليس على `auth:sanctum`.
- الاختبار التشغيلي أثبت:
  - Cookies فقط → `401`
  - Bearer / `wsa_token` فقط → `200`
  - Cookies + Bearer → `200`
- عند تسجيل الدخول، يتم إنشاء Personal Access Token ويُخزن حاليًا في `localStorage['wsa_token']`.
- العميل يرسل الرمز في `Authorization: Bearer`.
- Flutter يعتمد أيضًا على PAT، لكن تخزينه هناك منفصل عن Web.
- Public Research / Feedback / Crop لا تحتاج إلى PAT في المسارات العامة.

### المخاطر التقنية المثبتة

هذه ليست مشكلة وظيفية حالية، لكنها تمثل Technical Debt ومخاطر أمنية ينبغي معالجتها لاحقًا:

1. تخزين PAT في `localStorage` يعني أنه يمكن لكود JavaScript يعمل في نفس الأصل الوصول إليه.
2. الـ PAT الحالي يُنشأ بصلاحيات `['*']`.
3. المستخدم العادي لا يملك حاليًا مدة انتهاء مفعّلة مماثلة لرمز Platform Administrator.
4. تسجيل الخروج يلغي الرمز الحالي فقط؛ الرموز الأخرى للمستخدم قد تبقى فعالة.
5. تغيير كلمة المرور لا يؤدي حاليًا إلى إلغاء جميع PATs.
6. تعطيل الحساب لا يعني بالضرورة إبطال PATs الموجودة وفق التدقيق الحالي.

### القرار الحالي

**لا نحذف `wsa_token` ولا نعيد تصميم المصادقة الآن.**

تم فصل هذه المشكلة عن إصلاح Phase 1 وعن Phase 2 Scientific & Crop Foundation، حتى لا نخلط إصلاحًا معماريًا كبيرًا مع إصلاحات البحث العلمي والمحاصيل.

### الحل المستقبلي المقترح

عند فتح هذه المشكلة في مرحلة مستقلة:

- **Web SPA:** الانتقال إلى Sanctum Stateful Session كمصدر هوية، مع إزالة الاعتماد على PAT في `localStorage`.
- **Flutter / Admin Mobile:** الاستمرار في استخدام PAT مع تخزين آمن.
- **External API:** الاستمرار في Client Credentials.
- مراجعة دورة حياة Tokens: انتهاء الصلاحية، الإلغاء عند تغيير كلمة المرور، إلغاء جميع الجلسات عند تعطيل الحساب، وإدارة الأجهزة والجلسات.
- تنفيذ Migration تدريجي مع اختبارات Regression كاملة قبل إزالة المسار القديم.

### المرجع

التدقيق المعماري المفصل محفوظ في تقرير **wsa_token audit** الذي أثبت أن الرمز مطلوب في المعمارية الحالية، وأن ترحيله يجب أن يكون مشروع مصادقة مستقلًا وليس تعديلًا جانبيًا.

**قاعدة مهمة عند العودة للمشكلة:** لا يتم حذف `wsa_token` أو تغيير آلية المصادقة الحالية قبل بناء واختبار البديل الكامل للمصادقة عبر Session، ثم إجراء Regression شامل على Web SPA والـ Admin Web وباقي العملاء.
