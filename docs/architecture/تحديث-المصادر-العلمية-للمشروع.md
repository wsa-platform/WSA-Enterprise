# تحديث المصادر العلمية للمشروع — قرار معماري وجدول المقارنة

**Decision ID:** ADR-023  
**Status:** ACCEPTED — Architectural Decision  
**Scope:** Scientific source capability, query compilation, retrieval, evidence preservation  
**Branch:** `docs/update-scientific-sources`  
**Base GitHub HEAD:** `3946e4fe574382472228f524dd87d9f62defb18a`  
**Date:** 2026-09-29

## 1. القرار

اعتماد منظومة المصادر العلمية الموسعة كطبقة **Source Capability / Retrieval** في WSA-Enterprise، مع الحفاظ على الهوية العلمية للسؤال والإجابة.

المصدر العلمي لا يصبح سلطة دلالية على السؤال. السلطة الدلالية تبقى لـ **Canonical Scientific Question (CSQ)**، ثم تُشتق منه مواصفات الاسترجاع والاستعلامات الخاصة بكل مصدر.

القاعدة الأساسية:

`Canonical Scientific Question → Query Expansion → Source Capability Matching → Source-specific Query → Evidence → Validation → Answer`

ولا يجوز أن تتحول نتائج مصدر أو كلمات مفتاحية مصدرية إلى سؤال علمي جديد.

## 2. الحفاظ على هوية السؤال

يجب أن تبقى الأدوار التالية مستقلة ومجمدة في CSQ:

- ENTITY
- TARGET
- PROCESS
- PROPERTY
- RELATION

وتظل هذه الأدوار المرجع الوحيد للمعنى العلمي. لا يجوز للمصدر أو للـquery variant إعادة تعريفها.

يمكن توليد مرادفات وأسماء علمية وصيغ بحث مختلفة، لكن هذه تظل **Retrieval Artifacts** وليست semantic authority.

## 3. بناء الاستعلام

يقسم الاستعلام إلى:

1. Canonical Question Identity
2. Query Expansion Plan
3. Retrieval Specification
4. Source-specific Query Plan

وتشمل عناصر الاستعلام عند الحاجة:

- entity / crop / animal / fish / insect
- target
- process / intervention
- property
- relationship
- measurement
- geography
- time
- population
- comparator
- evidence need

ويجب أن يبقى الحد الفاصل:

**Question Meaning ≠ Search Query ≠ Search Result ≠ Evidence ≠ Answer**

## 4. نموذج إضافة المصادر

لا تتم إضافة كل مجلة كـAdapter مستقل.

بدلًا من ذلك، يسجل كل مصدر في **ScientificSourceCapabilityProfile** يحدد:

- source identity
- source type
- domain
- modalities
- geographic strengths
- query features
- filters
- API / metadata mechanism
- full-text availability
- evidence role
- peer-review characteristics
- overlap
- unique incremental value

ثم يختار Source Selector المصادر المناسبة للسؤال.

## 5. عدم تغيير العقود المغلقة

هذا القرار لا يغيّر:

- CSQ V1
- R1–R7
- RetrievalSemanticContract safety rules
- query variant budgets
- AccuracyGate
- RelevanceGate
- Evidence axes
- AnswerComposer
- DIRECT evidence rules
- final-answer confidence threshold 0.50
- Home/Crop isolation
- ScientificUserPresentation
- result identity / first-wins dedup
- FAOSTAT guards and verified mappings

أي تنفيذ لاحق يجب أن يمر بمراحل:

**Evidence → Root Cause → Repair → Test → Regression → Verification → Commit**

## 8. قواعد الهوية ومنع التكرار

يجب إنشاء Source Identity مستقلة عن الاسم الظاهر.

مثال JISHS/eJHS:

- نفس الهوية العلمية للمجلة.
- eJHS هو الاسم التاريخي.
- JISHS هو الاسم الجديد.
- تغيير الاسم لا ينشئ مصدرًا ثانيًا.

كما يجب استخدام، عند توفرها:

- ISSN-L
- ISSN/eISSN
- DOI
- publisher
- OpenAlex source ID
- Crossref identity
- repository identity

لمنع التكرار.

## 9. أدوار الأدلة

المصدر لا يعني تلقائيًا أن كل نتيجة منه Direct Evidence.

يجب حفظ:

- source_type
- document_type
- peer_review_status
- directness
- claim_relation
- disposition
- confidence
- provenance

وتبقى المحاور منفصلة وفق R6.

مثال:

FAOSTAT قد يكون قويًا في **production/yield statistics** لكنه ليس دليلًا تجريبيًا مباشرًا على أن معاملة زراعية سببت زيادة في الإنتاج.

وبالمثل، صفحة مؤسسة بحثية قد تكون **institutional/contextual evidence**، بينما المقال التجريبي المنشور منها يمكن أن يصبح **direct scientific evidence**.

## 11. طريقة التنفيذ المستقبلية

لا يجيز هذا القرار تعديل الكود مباشرة.

التنفيذ المقترح:

1. Forensic audit لـSource Registry وCapability Profiles وSource Selector.
2. إنشاء Source Identity/Capability model دون تغيير CSQ.
3. إدخال المصادر الأساسية أولًا.
4. ربط كل مصدر بالـmodality والقدرات والفلاتر.
5. توليد source-specific query من CSQ/RetrievalSpecification.
6. تنفيذ البحث.
7. Normalization إلى ScientificSearchResult.
8. Evidence validation.
9. Deduplication باستخدام الهوية العلمية للمصدر والنتيجة.
10. اختبار Query Identity Preservation.
11. اختبار Query Drift.
12. اختبار multilingual equivalence.
13. Regression كامل.
14. Commit منفصل لكل مرحلة.

## 12. Hard-stop conditions

يجب التوقف فورًا إذا:

- أعاد مصدر تعريف ENTITY/TARGET/PROCESS/PROPERTY/RELATION.
- أصبحت query variants مصدر المعنى.
- أصبح عنوان أو نتيجة بحث هو السؤال الجديد.
- تغيرت حدود RSC أو CSQ دون قرار منفصل.
- حدث خلط بين Directness وclaim_relation وdisposition.
- تغير threshold 0.50.
- تغير Composer أو Accuracy/Relevance gates.
- حدث duplicate source بسبب تغيير اسم مجلة.
- تم الكتابة فوق WIP أو استخدام reset/restore/clean/stash/rebase/force-push.
- تم تعديل الكود قبل إتمام forensic audit.

## 13. قرار التنفيذ

**تم اعتماد الاتجاه المعماري والتوثيق.**

هذا القرار لا يعني أن جميع المصادر ستُنفذ دفعة واحدة. الأولوية تكون للمصادر ذات القيمة البنيوية العالية، ثم المصادر التخصصية، ثم المصادر المؤسسية المتخصصة.

**Documentation-only decision:** لا يوجد في هذا القرار أي تعديل على منطق البحث أو AnswerComposer أو CSQ.
