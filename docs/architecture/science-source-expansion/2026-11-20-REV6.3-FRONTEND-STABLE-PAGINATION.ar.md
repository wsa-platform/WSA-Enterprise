# WSA-Enterprise — Revision 6.3
## Frontend Integration & Stable Pagination

### عقود API الفعلية (من الكود)

**Query:** `POST /api/v1/public/research-agent/query`  
Body: `{ organization?: string, query: string }` (organization غير سلطاني — MODEL B)

Response يتضمن عند النجاح/الاكتمال (Rev 6.1+):
- `user_presentation`, `multi_answers`, `stable_result_set`
- `stable_result_set.result_set_id`, `page_size`, `total_answers`, `total_pages`, `page` (الصفحة 1)
- `failure_class`, `failure_code`

**Results:** `GET /api/v1/public/research-agent/results?result_set_id=&page=`  
- عزل Tenant عبر `PublicTenantResolver` (لا اعتماد على organization من الواجهة كصلاحية)
- Response: `answers` (≤10), `page`, `total_pages`, `rerun_performed: false`, observability بدون إعادة بحث

### مصدر الحقيقة
`StableAnswerResultSet` يحدد الترتيب والهوية والصفحات. Episode المحلي يحفظ استجابة العرض/الاستعادة فقط ولا يعيد ترتيب الإجابات.

### دورة الواجهة
1. بحث جديد → Query → حفظ `result_set_id` → عرض `page` الأولى  
2. تنقل → Results فقط (لا Query)  
3. فشل تحميل صفحة → الإبقاء على الصفحة الحالية + رسالة واضحة  
4. فشل مصنّف عبر `failure_class` برسائل عربية دون رموز خام أو Confidence
