## B. Root Cause

| البند | الدليل |
|---|---|
| المسار الفعلي | `/var/www/html/storage/app/scientific_stable_results` ← `storage_path('app/scientific_stable_results')` |
| نوع الملفات | Bind mount Windows Docker Desktop: `G:\` على `/var/www/html` نوع **9p** (metadata) |
| PHP-FPM master | UID `0` (root) — `php-fpm: master` |
| PHP-FPM workers | UID `33` (`www-data`) — `php-fpm: pool www`؛ `user=www-data` / `group=www-data` |
| آلية الفشل | مجلدات/ملفات أُنشئت كـ `root` (مثل `docker exec` كـ root) بصلاحيات `755` منعت كتابة `www-data` → `stable_result_set.status=result_set_failure` |
| entrypoint السابق | لم يُهيّئ مسار StableAnswerResultSet قبل قبول الطلبات |
| إصلاح يدوي تاريخي (6.5) | `chown` لحظي فقط — لا يعيش دورة إعادة إنشاء الحاوية |

## C. Implemented Design

**الحل المختار:** تهيئة ضيقة في `docker-entrypoint.sh` قبل `exec php-fpm`:

1. إنشاء `storage/app/scientific_stable_results` إن لم يوجد.
2. عند التشغيل كـ root: `chown www-data:www-data` + `chmod 2775` للجذر ومجلدات المنظمة (عمق 1).
3. لا `chmod 777`، لا تعديل شجرة `storage` كاملة.
4. Idempotent — لا حذف بيانات.
5. Compose يربط السكربت: `./backend/docker-entrypoint.sh:/usr/local/bin/docker-entrypoint.sh:ro` حتى تسري التعديلات دون إعادة بناء صورة كاملة.
6. Dockerfile: إنشاء المسار + `chown` طبقة الصورة (احتياطي لغير Compose).
7. المتجر: كتابة ذرّية (tmp→rename) + `chmod 0664`؛ رمي استثناء عند فشل الكتابة؛ تسجيل تحذيري عند فشل الإنشاء في الوكيل.

**بدائل مرفوضة:** `chmod -R 777`؛ تشغيل عمال FPM كـ root؛ sidecar مميز غير مقيّد.
