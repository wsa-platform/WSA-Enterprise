# WSA-Enterprise — Restore Remaining Services Safely
## الهدف
استكمال استعادة بيئة WSA-Enterprise بعد نجاح تشغيل الخدمات التالية:
- PostgreSQL: `wsa-enterprise-postgres-1`
- Redis: `wsa-enterprise-redis-1`
- Backend: `wsa-enterprise-backend-1`
- Frontend: `wsa-enterprise-frontend-1`
- Nginx: `wsa-enterprise-nginx-1`
التطبيق يعمل محليًا على `http://127.0.0.1:8079/` وقد أكد المستخدم عدم وجود مشكلات ظاهرة.
افحص الخدمات المتبقية واستعد ما يلزم منها وفق الشروط التالية.
## 1. Queue وScheduler
افحص الحاويتين الأصليتين:
- `wsa-enterprise-queue-1`
- `wsa-enterprise-scheduler-1`
قبل التشغيل، تحقق من:
- الصور والإعدادات والـ mounts والشبكات.
- الأوامر الفعلية التي تشغّلها كل حاوية.
- سبب الإيقاف السابق Exit 137 وسجلاتها المتاحة.
- اتصالها بـ PostgreSQL وRedis.
- ما إذا كانت ستنفذ مهامًا تكتب في قاعدة البيانات أو تعالج أعمالًا معلقة عند بدء التشغيل.
- عدم الحاجة إلى إعادة إنشاء الحاوية أو تعديل ملفات المشروع.
إذا كانت الحاويتان أصليتين وإعداداتهما سليمة، ولا يوجد خطر معروف من تنفيذ مهام مؤجلة أو مكررة، شغّل كل حاوية باستخدام `docker start`، واحدة في كل مرة، وتحقق من حالتها وسجلاتها قبل تشغيل التالية.
إذا ظهرت مهام معلقة قد يؤدي تشغيلها إلى تغييرات غير متوقعة، أو لم يمكن تحديد سلوكها، فتوقف عن تشغيل الحاوية المعنية وقدّم التشخيص.
## 2. R7 Store PostgreSQL
افحص الحاوية:
`wsa-r7-store-pg-20261015`
تحقق من:
- سبب وجودها ووظيفتها.
- قاعدة البيانات والـ Volume المرتبطين بها.
- السجلات السابقة وحالة الإيقاف.
- كونها مخزن اختبار منفصلًا أم خدمة لازمة للتطبيق الحالي.
- الشبكة المعزولة `NetworkMode=none` وأثرها على أي مستهلك محتمل.
لا تشغّلها إلا إذا أثبتت الأدلة أنها خدمة لازمة للاستعمال الحالي، وأن تشغيلها آمن ولا يتطلب تعديل الشبكات أو البيانات. خلاف ذلك، اتركها متوقفة وسجّل السبب.
## 3. Backup Verification PostgreSQL
افحص الحاوية:
`wsa-backup-verification-pg`
حدّد إن كانت مجرد بيئة مؤقتة للتحقق من النسخ الاحتياطية. لا تشغّلها تلقائيًا إذا لم تكن جزءًا من تشغيل التطبيق أو عملية تحقق مطلوبة حاليًا.
لا تحذف الحاوية أو الـ Volume، ولا تنفذ restore.
## 4. الحاوية اليتيمة
أبقِ:
`wsa-enterprise-postgres-1-orphan`
متوقفة دائمًا في هذه المهمة؛ لأنها تستخدم Volume قاعدة البيانات نفسها التي تستخدمها PostgreSQL الأصلية. لا تشغّلها بالتزامن معها.
## 5. قيود إلزامية
- لا تستخدم `docker compose up/down`.
- لا تعِد إنشاء أي حاوية.
- لا تنفّذ migrations أو restore أو seeders.
- لا تعدّل `.env` أو ملفات المشروع أو إعدادات الشبكات.
- لا تحذف أو تغيّر أي Volume أو قاعدة بيانات.
- لا توقف الخدمات الخمس العاملة حاليًا.
- لا تنفّذ Git commit أو push أو reset أو clean.
- لا تشغّل حاويات الاختبار تلقائيًا لمجرد أنها متوقفة.
إذا فشلت حاوية أو احتاجت إلى تغيير غير مصرح به، أوقف الإجراء المتعلق بها فقط، واجمع السجلات والأدلة، ولا تُجرِ إصلاحًا تلقائيًا.
## 6. التقرير النهائي
قدّم تقريرًا واحدًا بالعربية يوضح لكل حاوية:
- وظيفتها المثبتة.
- حالتها السابقة والنهائية.
- ما إذا شُغّلت أم تُركت متوقفة.
- نتيجة فحص الصحة والسجلات.
- أي مخاطر أو تبعيات أو إجراءات متبقية.
الهدف هو استعادة الخدمات اللازمة فعليًا مع الحفاظ على سلامة المشروع وبياناته، وليس الوصول إلى رقم 10/10 حاويات عاملة بأي ثمن.
