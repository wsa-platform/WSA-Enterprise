## 2. قواعد السلامة الإلزامية

- لا تشغّل migrations أو أوامر Artisan التي تغيّر قاعدة البيانات.
- لا تستخدم `migrate:fresh` أو `db:wipe` أو rollback أو أوامر حذف البيانات.
- لا تنشئ قواعد بيانات أو أدوار مستخدمين جديدة.

## 3. المرحلة الأولى — جرد الملفات
افحص المجلد المحدد ومحتوياته الفرعية بصورة تكرارية، باستخدام عمليات قراءة فقط.
سجّل لكل ملف ذي صلة:
- المسار الكامل.
- الاسم والامتداد.
- الحجم بالبايت وMB أو GB.
- تاريخ آخر تعديل.
- نوع الملف الفعلي إن أمكن التحقق منه.
- هل يبدو ملف قاعدة بيانات، أو نسخة SQL، أو أرشيفًا مضغوطًا، أو بيانات وصفية، أو ملف إعدادات.
ابحث عن الملفات ذات الامتدادات، على سبيل المثال لا الحصر:
- `.sqlite`, `.sqlite3`, `.db`
- `.sql`, `.sql.gz`
- `.dump`, `.backup`, `.bak`
- `.zip`, `.7z`, `.tar`, `.gz`
- ملفات metadata أو manifests أو تقارير النسخ الاحتياطي.
لا تستبعد ملفًا لمجرد أن امتداده غير مألوف أو أن اسمه لا يتضمن `wsa_enterprise`.
## 4. المرحلة الثانية — تحديد محرك قاعدة البيانات
حدّد المحرك من أدلة الملف الفعلية، لا من التخمين أو أسماء الملفات وحدها.
افحص، حسب ما تسمح به الملفات:
- ترويسات الملفات وتواقيعها (file signatures).
- بنية ملفات SQLite باستخدام فتح قراءة فقط أو فحص SQLite آمن.
- محتوى ملفات SQL وبياناتها الوصفية دون تنفيذها.
- مؤشرات نسخ MySQL/MariaDB أو PostgreSQL أو SQL Server أو غيرها.
- ملفات إعدادات النسخ الاحتياطي أو manifests ذات الصلة.
إذا كان الملف أرشيفًا، افحص قائمة محتوياته أولًا دون فكّه فوق الملفات الموجودة. إذا احتجت إلى استخراج مؤقت للفحص، فاستخدم مجلدًا منفصلًا خارج مجلد النسخة الأصلية، ولا تستبدل أي ملف.
لا تنفّذ ملفات SQL ولا تستوردها.
## 5. المرحلة الثالثة — تحديد قاعدة بيانات Laravel الرئيسية
اربط الأدلة بالمعمارية الفعلية لمشروع `G:\WSA-Enterprise`، مع الحفاظ على الفصل بين:
1. قاعدة بيانات Laravel الرئيسية.
2. مخزن Capability Records / CapVer.
3. مخزن Scientific LocalIndex.
4. أرشيف Mission Artifacts.
5. أي قواعد بيانات للاختبارات.
تحقق من أسماء الجداول والمخطط أو metadata عند توفرها، دون كشف سجلات المستخدمين أو محتوى حساس. حدّد ما إذا كانت النسخة تحتوي على جداول المشروع الأساسية أو مجرد مخزن فرعي.
قارن أسماء الجداول والمخططات مع migrations وإعدادات المشروع الحالية، لكن لا تعدّل المشروع.
لا تعتبر وجود ملف SQLite دليلًا كافيًا على أن Laravel يستخدمه لقاعدة البيانات الرئيسية.
## 6. المرحلة الرابعة — تقييم السلامة وقابلية الاستخدام
لكل مرشح لقاعدة البيانات، سجّل:
- نوع المحرك المرجح ودرجة الثقة في الاستنتاج.
- هل يمكن قراءة الملف أو التحقق من بنيته؟
- هل توجد مؤشرات على اكتمال النسخة؟
- هل توجد بيانات أو جداول تتوافق مع مشروع WSA-Enterprise؟
- هل النسخة مستقلة أم تعتمد على ملفات إضافية؟
- هل الملف يبدو نسخة كاملة أم جزئية؟
- ما الذي لا يزال مجهولًا؟
- ما الفحوص الآمنة التالية اللازمة قبل أي استعادة؟
إذا كان SQLite، استخدم فحوصًا للقراءة فقط مثل `PRAGMA quick_check` عند التأكد من أن العملية لن تكتب إلى الملف، وفضّل فتحه باستخدام وضع القراءة فقط. لا تستخدم أوامر إصلاح أو تغييرات على قاعدة البيانات.
إذا كان نوع آخر، استخدم فحوص التحقق غير المدمرة المناسبة، دون تشغيل خادم أو استيراد البيانات أو تعديل المصدر.
## 7. المرحلة الخامسة — تقرير النتائج
قدّم تقريرًا هندسيًا بالعربية يتضمن:
1. **الملخص التنفيذي:** هل عُثر على قاعدة البيانات الأصلية أم لا؟
2. **جدول الملفات المرشحة:** المسار، النوع، الحجم، الدور المحتمل، ودرجة الثقة.
3. **محرك قاعدة البيانات:** الدليل الذي يثبته، مع فصل المؤكد عن المحتمل.
4. **تحديد قاعدة Laravel الرئيسية:** الأدلة التي تميزها عن المخازن الفرعية.
5. **فحص السلامة:** ما الذي تم فحصه فعلًا ونتائج كل فحص.
6. **المقارنة مع المشروع الحالي:** ما الذي يتطابق وما الذي لا يمكن إثباته.
7. **المخاطر والفجوات:** الملفات الناقصة أو الأجزاء غير المتحققة.
8. **التوصية التالية:** خطوة واحدة آمنة ومحددة، دون تنفيذها في هذه المهمة.
