- Local path: `G:\WSA-Enterprise`

الهدف هو الإجابة بالأدلة عن الأسئلة التالية:

2. ما المحرك الذي يتوقع Laravel استخدامه وفق الإعدادات الحالية؟

4. هل يستخدم المشروع PostgreSQL أو MySQL/MariaDB أو SQLite أو SQL Server أو محركًا آخر؟
5. هل كان الاتصال السابق عبر Docker أو خادم آخر أو خدمة محلية؟
6. ما طريقة الاتصال الحالية، وما الذي يمنعها من العمل مع PostgreSQL المحلي؟
7. ما الخطوات الآمنة المطلوبة لتوصيل Laravel بقاعدة البيانات الصحيحة دون فقد بيانات؟

### 3. فحص إعدادات Laravel
افحص للقراءة فقط:
- `backend/.env`
- `backend/.env.example` إن وجد
- `backend/config/database.php`
- `backend/bootstrap/cache/config.php` إن وجد، للتحقق من احتمال استخدام إعدادات مخزنة مؤقتًا، مع عدم عرض الأسرار.
- `backend/composer.json`
- ملفات إعداد الاختبارات وأي ملفات إعداد خاصة ببيئات التطوير.
استخرج دون أسرار:
- قيمة `DB_CONNECTION`.
- `DB_HOST` و`DB_PORT` و`DB_DATABASE` و`DB_USERNAME`.
- نوع الاتصال الافتراضي الذي يحدده `config/database.php`.
- تعريفات اتصالات قواعد البيانات الإضافية.
- هل إعدادات Laravel الفعلية قد تختلف عن `.env` بسبب Configuration Cache.

لا تكتفِ بقيمة `.env`؛ ميّز بين الإعداد المكتوب والإعداد الذي يستخدمه التطبيق فعليًا، ولا تدّعِ معرفة الإعداد الفعلي وقت التشغيل دون دليل.
### 4. تحديد محرك SQL المستخدم في المشروع
ابحث عن أدلة في:

- أي ملفات إعداد أو سكربتات تشير إلى MySQL أو PostgreSQL أو SQLite أو SQL Server أو خدمات خارجية.
ابحث عن:
- `DB_CONNECTION`

- `mysql`
- `mariadb`

- `sqlsrv`

لا تعتبر وجود حزمة PDO أو تعريف migration دليلًا كافيًا على أن المحرك مستخدم فعليًا.
### 5. تحديد مكان البيانات الفعلية
