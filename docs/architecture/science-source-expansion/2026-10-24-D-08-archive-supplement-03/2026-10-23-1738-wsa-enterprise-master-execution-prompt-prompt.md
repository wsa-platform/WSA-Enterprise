## القسم 7 — بوابة Commit وPush للجولة الأولى

**لا تنفذ Commit أو Push إلا إذا اكتملت شروط القبول الإلزامية للجزء المراد الالتزام به، وتمت مراجعة كل ملف في الالتزام.**

قبل الالتزام:
1. راجع `git status` و`git diff` والملفات الجديدة.
2. أنشئ قائمة ملفات صريحة للالتزام.
3. استبعد العمل السابق غير المرتبط، والملفات الحساسة، وقواعد البيانات، وملفات recovery، ومخرجات الاختبارات غير المعتمدة، وكل ملف غير مفهوم.
4. لا تستخدم `git add .` أو `git add -A` بصورة عمياء.
5. لا تضمّن تغييرات CapVer السابقة أو تغييرات المستخدم غير المرتبطة بالجولة الأولى.
6. إذا كان ملف مثل ADR-023 يحتوي تعديلات مختلطة لا يمكن فصلها بأمان، فلا تضمّنه في الالتزام حتى تُحل المشكلة بطريقة آمنة وموثقة.

بعد اجتياز البوابة:
1. أنشئ `commit` مستقلًا برسالة تصف العمل المنجز فعليًا.
2. تحقق من معرّف الالتزام ومحتوياته.
3. تحقق من حالة الفرع البعيد قبل الرفع.
4. نفّذ `push` إلى الفرع المعتمد إذا كانت الحالة تسمح.
5. تحقق من نتيجة الرفع وتطابق `HEAD` المحلي مع الفرع البعيد.
6. سجّل معرّف الالتزام والملفات المشمولة ونتائج الاختبارات ونتيجة الرفع.

لا تستخدم:
- `git reset --hard`
- `git clean -fd`
- `git push --force`
- `git push --force-with-lease`
- أي أمر يعيد كتابة التاريخ أو يحذف عملًا سابقًا.

إذا تعذر قبول جزء من الجولة، فلا تنشئ التزامًا يوحي باكتماله. يمكنك إكمال الأجزاء المستقلة الآمنة، لكن لا تلتزم بها إلا إذا كان نطاقها واضحًا ومستوفيًا لمعايير قبولها ويمكن فصلها بأمان.

إذا نجح Commit وفشل Push، احتفظ بالالتزام المحلي وسجّل `COMMITTED — PUSH PENDING`. لا تعِد كتابة التاريخ ولا تحاول تجاوز التعارض بالقوة.

## القسم 8 — نقطة التوقف والتقرير النهائي

أنشئ نقطة توقف فريدة وفق ملف القواعد المشتركة، ولا تستبدل نقطة توقف موجودة. إذا كان إنشاء ملف داخل المستودع سيضيف ضوضاء إلى الالتزام، فاستخدم موقعًا آمنًا خارج مجموعة ملفات الالتزام وسجّل مساره الحقيقي.

أرسل تقريرًا عربيًا واحدًا شاملًا يتضمن:

1. **ملخص تنفيذي:** هل كان خط الأساس آمنًا؟ وهل بدأت الجولة الأولى؟
2. **نسخ القواعد:** هل قُرئت الملفات كاملة؟ وما الاختلافات؟
3. **حالة Git:** المسار والفرع و`HEAD` قبل العمل وبعده.
4. **الجرد:** الأعداد الفعلية للملفات المتتبعة المعدّلة وغير المتتبعة والمحذوفة والمضافة إلى Staging، مع مسارات وتصنيفات مفصلة.
5. **حماية العمل السابق:** ما الذي حُفظ واستُبعد، وما الذي بقي غير مفهوم.
6. **ADR-023:** تحليل التغييرات المختلطة وقرار التعامل معها.
7. **حالة Layers A–D:** `IMPLEMENTED` أو `TESTED` أو `VERIFIED` أو `PARTIAL` أو `BLOCKED`، مع سبب وأدلة لكل حالة.
8. **الاختبارات:** الأوامر الفعلية والنتائج والإخفاقات وما لم يُنفّذ.
9. **Commit:** معرّف الالتزام ورسالة الالتزام والملفات المشمولة، أو سبب عدم إنشائه.
10. **Push:** النتيجة الفعلية وحالة الفرع البعيد، أو سبب التعذر.
11. **نقطة التوقف:** المسار الفعلي ومحتوياتها الأساسية.
12. **المشكلات المتبقية:** ما الذي يمنع الإغلاق أو يحتاج إلى قرار لاحق.

لا تستخدم `COMPLETE` أو `VERIFIED` إلا بوجود أدلة تدعمها. إذا لم تُنفّذ الجولة بسبب نقص المرفقات أو مانع أمني، فاذكر ذلك صراحةً ولا تدّعِ تنفيذًا لم يحدث.
